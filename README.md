# Stride Physical Therapy & Wellness — website (Next.js)

Public website for `stridephysical.com`, migrated from the React/Vite frontend in
`C:\development\stride-platform\frontend` to the Next.js App Router. Design, copy, images, routes, metadata and the
appointment integrations are unchanged. The Laravel API remains the backend: the browser calls it directly (CORS), as
before, with the same endpoints and payloads.

| Path | What it is |
| --- | --- |
All application code lives in `src/` (Next.js `src` folder convention); the project root holds configuration,
`public/`, build/test scripts, end-to-end tests and source assets. The `@/*` import alias points at `src/`.

| Path | What it is |
| --- | --- |
| `src/app/` | App Router routes only: one `page.tsx` per URL, `layout.tsx` (header, footer, JSON-LD), `not-found.tsx`, `sitemap.ts` (→ `/sitemap.xml`), `robots.ts` (→ `/robots.txt`) |
| `src/proxy.ts` | Unknown service/condition/resource slugs → not-found page with HTTP 404 |
| `src/views/` | Page components (formerly `src/pages/`, renamed so Next.js does not treat it as a Pages Router) |
| `src/components/`, `src/data/`, `src/config/`, `src/services/`, `src/styles/`, `src/utils/`, `src/types/`, `src/hooks/` | Carried over from the Vite project |
| `src/seo/` | `head.ts` builds every page's metadata (`pageMetadata()` → Next.js Metadata); `routeMeta.ts` holds per-route titles and descriptions; `structuredData.ts` the clinic JSON-LD |
| `src/assets/` | Site images, imported statically (fingerprinted); `src/data/generated/imageFiles.ts` lists them |
| `public/` | Files served at fixed URLs: favicon, touch icon, social preview image |
| `brand-assets/` | Original source files kept unchanged (e.g. the Coming Soon poster PNG); build scripts derive the site images from them |
| `scripts/` | Image build scripts and `verify-routes.mjs` (HTTP checks of a running build) |
| `e2e/`, `e2e-http/` | Playwright tests: demo mode, and the real HTTP adapters against an intercepted fake API |
| `next.config.ts` | Redirects (`/wellness`, `/physical-therapy`, `www` → apex, all 301) and security headers carried over from `.htaccess` |

`robots.txt` and `sitemap.xml` are generated by `src/app/robots.ts` and `src/app/sitemap.ts` from the build's
`SITE_URL`/`SITE_ENV`; do not add static copies (a copy at the project root is never served, and one in `public/`
would conflict with the generated routes).

## Routes

`/`, `/services` (+12), `/what-we-treat` (+14), `/patient-resources` (+5 pages, +3 articles), `/about`,
`/about/meet-dr-gadly`, `/contact`, `/contact/schedule-appointment` (noindex, not in the sitemap). Every page is
statically generated at build time. Redirects: `/wellness` → `/services`, `/physical-therapy` →
`/services/physical-therapy` (query string kept). Trailing slashes redirect to the canonical URL.

## Environment variables

Copy `.env.example` to `.env.local` for development. For staging/production builds, set the values in the build
environment. **Do not create `.env.production`**: `next build` loads it automatically, including for the test builds.

| Variable | Exposed to the browser | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | yes (public URL only) | Laravel API base, e.g. `https://api.stridephysical.com/api/v1` |
| `NEXT_PUBLIC_USE_MOCK_API` | yes | `true` (default) = demo adapter, nothing is sent; `false` = real API |
| `NEXT_PUBLIC_API_TIMEOUT_MS` | yes | Request timeout (default 15000) |
| `SITE_URL` | no (server/build only) | Canonical origin for canonical/OG URLs, sitemap and robots, e.g. `https://stridephysical.com`. Empty locally and on staging |
| `SITE_ENV` | no (server/build only) | `staging` = staging notice + `noindex, nofollow` on every page |

Never put secrets in `NEXT_PUBLIC_` variables: they are inlined into the JavaScript bundle. Backend credentials
(SendGrid, SPRY, database, `APP_KEY`) stay in the Laravel backend's own `.env`.

| Target | Values |
| --- | --- |
| Local | defaults (mock API, no `SITE_URL`) |
| Staging | `NEXT_PUBLIC_USE_MOCK_API=false`, `NEXT_PUBLIC_API_BASE_URL=https://api-staging.stridephysical.com/api/v1`, `SITE_ENV=staging` |
| Production | `NEXT_PUBLIC_USE_MOCK_API=false`, `NEXT_PUBLIC_API_BASE_URL=https://api.stridephysical.com/api/v1`, `SITE_URL=https://stridephysical.com` |

## Commands

```bash
npm ci
npm run dev          # http://localhost:3000 (mock API)
npm run check        # typecheck, lint, unit tests, production build
npm run test:e2e     # Playwright: builds in demo mode and runs against next start (installed Edge)
npm run test:e2e:http   # Playwright: real HTTP adapters against an intercepted fake API (nothing is sent)
# Route verification over HTTP (start the build first with the same SITE_URL / SITE_ENV):
npx next start -p 3100 & node scripts/verify-routes.mjs --base http://localhost:3100 --site-url https://stridephysical.com
```

Images: files in `src/assets/images/{site,home}` are imported statically through `src/data/generated/imageFiles.ts`
(fingerprinted under `/_next/static/media/`). After adding an image, run `node scripts/build-image-imports.mjs`.

Coming Soon poster: replace `brand-assets/posters/coming-soon-westmont.png` (keep the text column left of x = 1150).
`npm run build` regenerates the served WebPs first (`prebuild` → `scripts/build-poster-images.mjs`, skipped when the
PNG's SHA-256 matches `src/data/generated/posterMediaManifest.ts`). Commit the regenerated files with the PNG. If the
poster's words change, update the alt text and the mobile slide's copy in `src/views/HomePage.tsx`.

Hosting: the site needs a Node.js runtime (`next start`) or a platform that runs Next.js, because of the redirects,
the 404 handling in `src/proxy.ts` and the security headers. The old GoDaddy/Apache static upload (`.htaccess`) does not
apply to this build. Project conventions from the Vite project's `CLAUDE.md` (content sources, accessibility,
clinical-claims rules, API rules) still apply.
